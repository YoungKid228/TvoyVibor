# Твой выбор — профориентация «Экономика»

**ПГУ им. Шолом-Алейхема · направление «Экономика»**

Профориентационное PWA-приложение: школьники и студенты СПО/бакалавриата/магистратуры
проходят тесты, получают подборку подходящих профессий с процентом соответствия,
смотрят галерею профессий, фото ПГУ и материалы клуба молодого предпринимателя.
Приложение ставится на телефон как нативное и работает офлайн.

## Возможности

| Раздел | Что внутри |
|---|---|
| **Тесты** | Два теста (для школьников и для СПО/бакалавриата/магистратуры) по 20 вопросов + 20 коротких тестов по конкретным профессиям. Ответ по шкале 1–5, подсчёт соответствия по 20 профессиям. |
| **Галерея профессий** | 20 профессий: карточка с обязанностями, навыками, особенностями, привязкой к программе подготовки и кнопкой «пройти тест». |
| **Направления** | Программы подготовки (38.02.07 «Финансы и бухгалтерский учёт», 38.02.01, 38.03.01, 38.04.01) с условиями поступления, формами обучения, типами, дисциплинами и профессиями выпускников. |
| **Галерея ПГУ** | 30 фотографий учебного заведения с просмотром и перелистыванием. |
| **Клуб** | Материалы клуба молодого предпринимателя: колода из 12 фото, описание встреч, записи. |
| **Игра** | Мини-игра в пиксельном стиле. |

Общее: пиксельный визуальный стиль, анимированные фоны, полная работа офлайн после
первой загрузки, установка на домашний экран телефона.

## Как запустить локально

Требуется Node.js 20+ и npm.

```bash
npm install     # установка зависимостей
npm run dev     # http://localhost:5173 — режим разработки с HMR
```

Продакшен-сборка и просмотр именно собранной версии:

```bash
npm run build
npm run preview # http://127.0.0.1:4173
```

## Команды

```bash
npm install        # установка зависимостей
npm run dev        # режим разработки
npm run test       # модульные тесты (Vitest)
npm run build      # type-check (tsc -b) + production-сборка в dist/
npm run preview    # локальный просмотр сборки (http://127.0.0.1:4173)
npm run test:e2e   # сквозные тесты (Playwright, использует npm run preview)
```

## Деплой на GitHub Pages

Приложение — чистая статика (Vite + PWA), бэкенда нет. Основной вариант хостинга —
**GitHub Pages** (бесплатно): сайт собирается и публикуется автоматически при
каждом пуше в `main`.

> GitHub Pages на бесплатном плане работает только для **публичных** репозиториев,
> поэтому репозиторий проекта должен быть публичным.

### Как это работает

Workflow `.github/workflows/deploy.yml` состоит из двух job'ов:

1. `build` — `npm ci` → сборка с `BASE_PATH=/<имя-репозитория>/` → загрузка `dist`
   как артефакта Pages.
2. `deploy` — публикация артефакта через `actions/deploy-pages@v4`.

`BASE_PATH` подставляется в `vite.config.ts` и используется как `base` для Vite и
`vite-plugin-pwa`, а также как `start_url`/`scope` манифеста и в путях иконок.
Поэтому приложение корректно работает из подпапки `/<имя-репозитория>/`.

### Шаг 1. Открыть репозиторий и включить Pages

1. **Settings → General → Danger Zone → Change repository visibility → Change to
   public** (если репозиторий приватный).
2. **Settings → Pages → Source**: *Deploy from a branch*, ветка `main`,
   папка `/ (root)` → **Save**.

### Шаг 2. Публиковать изменения

```bash
git add -A
git commit -m "Описание изменений"
git push origin main
```

Workflow соберёт и опубликует сайт. Адрес: `https://<логин>.github.io/<имя-репозитория>/`.
Перезапустить сборку вручную можно через **Actions → Deploy to GitHub Pages →
Run workflow**.

### Шаг 3. Проверить результат

- Сайт открывается по HTTPS.
- Service worker зарегистрирован в scope `/<имя-репозитория>/`.
- Фото клуба и галереи ПГУ грузятся (кэшируются отдельно от precache).
- Манифест отдаётся с MIME `application/manifest+json`.
- Приложение открывается в standalone-режиме и работает без сети.

### Альтернатива: Cloudflare Pages

Если репозиторий нужно оставить приватным — подойдёт Cloudflare Pages (бесплатно,
безлимитный трафик, репозиторий подключается через GitHub App):

```bash
npm run build
npx wrangler login
npx wrangler pages project create tvoi-vybor
npx wrangler pages deploy dist --project-name tvoi-vybor
```

Подробности — в [`DEPLOY.md`](DEPLOY.md).

### Другие статические хостинги

Подойдёт любой хостинг статических файлов по HTTPS:

- **Netlify** — Build Command `npm run build`, Publish Directory `dist`.
- **Cloudflare Pages** — см. раздел выше.
- **Свой сервер** — отдать содержимое `dist/` как статику.

Для этих хостингов `BASE_PATH` не задаётся, сборка идёт в корень (`base: "/"`).

Требования: **HTTPS** (без него не работает service worker) и корректный MIME-тип
`.webmanifest`. Обновления подхватываются автоматически (`registerType: "autoUpdate"`).

## Архитектура приложения

Приложение — **одностраничное SPA без клиентского роутера**: активный раздел
хранится в состоянии `App`, а навигация — это набор вкладок в шапке. Поэтому
SPA-rewrite не требуется, а офлайн-переходы по URL обслуживает service worker
(Workbox `NavigationRoute → index.html`).

```
src/
├── App.tsx              # состояние активного раздела, маршрутизация по view
├── main.tsx             # точка входа, регистрация service worker
├── index.css            # Tailwind + пиксельные токены темы
├── components/          # переиспользуемые UI-блоки
│   ├── AppShell.tsx     # каркас: шапка, фон, футер
│   ├── InstallGate.tsx  # экран установки PWA (гайд + кнопка)
│   ├── PixelButton.tsx  # PixelCard.tsx  # ProgressBar.tsx
│   ├── GlitchText.tsx   # SpecialText.tsx
│   ├── DotMatrixBackground.tsx  # AsciiBackground.tsx
│   ├── ImageStackCarousel.tsx   # StickyCardStack.tsx
│   ├── ClubPhoto.tsx  # ProfessionCarousel.tsx
│   ├── QuestionScreen.tsx  # ResultScreen.tsx  # TestCard.tsx
│   └── PixelRunGame.tsx
├── pages/               # экраны по разделам
│   ├── HomePage.tsx  TestPage.tsx  ProfessionTestPage.tsx
│   ├── GalleryPage.tsx  ProfessionPage.tsx
│   ├── DirectionsPage.tsx  ProgramPage.tsx
│   ├── PguGalleryPage.tsx  ClubPage.tsx  GamePage.tsx
├── lib/
│   ├── scoring.ts            # формула расчёта процента соответствия
│   ├── professionTestScoring.ts  # шкалирование коротких тестов
│   ├── storage.ts            # сохранение прогресса в localStorage
│   ├── pwa.ts                # install prompt, standalone-режим
│   └── programLabel.ts       # подписи программ
├── data/                     # JSON с контентом
├── types/test.ts             # доменные типы
└── assets/                   # шрифт Minecraft, логотип, gif-подсказка установки
```

Ключевые решения:

- **Контент отделён от кода** — тексты, профессии, вопросы лежат в `src/data/*.json`,
  код их только рендерит и валидирует.
- **Фото не в precache** — 42 фотографии (~десятки МБ) кэшируются по требованию
  (`CacheFirst`, `app-photos`, 30 дней), чтобы первая загрузка была быстрой.
- **Прогресс теста сохраняется** в `localStorage`, тест можно продолжить после
  перезагрузки.
- **Все интерактивные элементы — настоящие `<button>`** с `aria-current`,
  `focus-visible` и минимальной высотой тапа 44 px.

## Структура данных

| Файл | Содержимое |
|---|---|
| `src/data/directions.json` | Направления подготовки (сейчас — «Экономика»). |
| `src/data/programs.json` | 4 программы подготовки: 38.02.07, 38.02.01, 38.03.01, 38.04.01. |
| `src/data/professions.json` | 20 профессий: `id`, `programId`, название, описание. |
| `src/data/professionDetails.json` | Карточки галереи: обязанности, навыки, особенности (`null` — «информация готовится»). |
| `src/data/tests.json` | 20 вопросов со знаковыми весами профессий + 2 теста со ссылками на вопросы. |
| `src/data/professionTests.json` | 20 коротких тестов по конкретным профессиям. |

Каждый опубликованный тест обязан содержать ровно 20 вопросов и проходить
валидацию `npm run test` (`tests/data.test.ts`): уникальность `id`, существование
профессий в весах, покрытие обеих аудиторий, распределение профессий по программам.

## Методика расчёта результата

Ответ на вопрос — оценка по шкале 1–5 («Совсем не моё» … «Абсолютно моё»). Веса
заданы единой моделью для всех 20 профессий: каждый вопрос относится к одному из
12 признаков, у каждой профессии есть профиль по этим признакам, вес вопроса для
профессии = значение профиля по признаку этого вопроса.

```
балл профессии за вопрос = w × (ответ − 3)
процент соответствия      = (raw − min) / (max − min) × 100
```

50 % — нейтрально. Пропущенные вопросы исключаются из расчёта. Подробно, со
сверкой с исходной методикой и контрольными примерами — в
[`docs/scoring-methodology.md`](docs/scoring-methodology.md).

## PWA: офлайн, манифест, установка

- **Service worker**: `registerType: "autoUpdate"` — новая сборка обновляет кэш
  сам, без ручного «обновить».
- **Precache**: `js, css, html, svg, ttf, woff, woff2, gif` — весь интерфейс,
  шрифт и анимации доступны офлайн сразу.
- **Runtime-кэш**: фотографии клуба и галереи ПГУ (`CacheFirst`, до 60 записей,
  30 дней).
- **Манифест**: имя «Твой выбор», `display: standalone`, тема `#c2410c`, фон
  `#fff7ed`, иконки 192/512 px + maskable.
- **Установка**: на Android доступен нативный промпт (кнопка «Установить
  приложение» на экране установки), на iOS — инструкция «Поделиться → На экран
  “Домой”». Кнопка «Продолжить в браузере» позволяет пользоваться приложением
  без установки.
- **Регистрация SW** — в `src/main.tsx`, только в production-сборке.

Если менялись иконки или манифест, уже установленное приложение нужно
**переустановить** — установленные PWA не всегда подхватывают новые иконки сразу.

Покрыто: валидация данных и методики подсчёта, сохранение прогресса, регистрация
service worker, манифест, офлайн-работа, экран установки, навигация по разделам,
колода фото клуба, галерея, базовая доступность.
