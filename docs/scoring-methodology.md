# Методика подсчёта результатов теста

Статус: действует единая модель весов для всех 20 профессий. Основание — признаки вопросов и профили профессий (раздел 3); исходная 3-вариантная методика (`docs/legacy-tests-3-options.json`) использована для сверки направлений (раздел 4), но весами больше не является.

## 1. Шкала ответов

Каждый вопрос оценивается по единой 5-балльной шкале:

| Значение | Подпись          | Согласие v = a − 3 |
|----------|------------------|--------------------|
| 1        | Совсем не моё    | −2                 |
| 2        | Скорее не моё    | −1                 |
| 3        | Нейтрально       | 0                  |
| 4        | Скорее моё       | +1                 |
| 5        | Абсолютно моё    | +2                 |

## 2. Формула подсчёта

Каждый вопрос `q` имеет вес влияния `w(q, p)` на каждую профессию `p` — целое от −3 до +3 (0 — влияния нет; как вес вычисляется — в разделе 3).

```
points(q, p) = w(q, p) × (a − 3)      — балл профессии за вопрос
raw(p)  = Σ points(q, p)              — по отвеченным вопросам
min(p)  = Σ (−2·|w(q,p)|)             — достижимый минимум
max(p)  = Σ (+2·|w(q,p)|)             — достижимый максимум
percent = round((raw − min) / (max − min) × 100)
```

- **0%** — ответы полностью против профессии, **50%** — нейтрально, **100%** — полностью за.
- Пропущенный вопрос исключается из `raw`, `min` и `max` — процент корректен при неполном прохождении.
- Сортировка стабильная: при равном проценте сохраняется порядок из `professions.json`. Экран показывает топ-3, наиболее и наименее подходящую профессии.
- В подсчёте участвуют профессии с хотя бы одним ненулевым весом (сейчас — все 20). Механизм исключения оставлен как защита на будущее.

## 3. Единая модель весов: признаки и профили

Веса всех 20 профессий назначаются **одним и тем же правилом** из двух таблиц.

**Шаг 1. Каждый вопрос относится к одному из 12 признаков:**

| Признак | Вопросы |
|---|---|
| Числа и расчёты (внимательность к точности) | q01, q02, q12 |
| Регламенты, законы, документы | q03, q04 |
| Анализ и закономерности | q05, q09 |
| Выявление рисков | q13 |
| Общение и помощь клиентам | q06, q07, q08, q18 |
| Продажи, устойчивость к отказам | q17 |
| Бюджеты и планирование | q10 |
| Переговоры с поставщиками | q11 |
| Усидчивость и автономность | q14, q15 |
| Понимание бизнеса и прибыли | q16 |
| Порядок и систематизация | q19 |
| Цифровые инструменты | q20 |

**Шаг 2. У каждой профессии — профиль по этим же признакам:**

| Значение | Смысл | Пример |
|---|---|---|
| +3 | ядро профессии | «общение с клиентами» → страховой агент |
| +2 | сильная связь | «цифры и расчёты» → бухгалтер по зарплате |
| +1 | вспомогательная связь | «цифровые инструменты» → операционист |
| 0 | нейтрально | «переговоры с поставщиками» → ипотечный специалист |
| −1 | против профессии | «анализ первопричин» → бухгалтер (работает по правилам) |
| −2 | противоположна профессии | «продажи» → кредитный аналитик (бэк-офис) |

**Шаг 3.** Вес вопроса для профессии = значение профиля профессии по признаку вопроса: `w(q, p) = профиль(p, признак(q))`.

Полные профили — в `src/data/tests.json` (`weights` у каждого вопроса). Контроль согласованности (проверяется тестами и прогоном):

- масса весов (сумма `|w|` по 20 вопросам) — от 19 до 32; ни одна профессия не ранжируется по 1–2 вопросам;
- у большинства профессий есть и положительные, и отрицательные связи — разделение результатов обеспечено;
- каждая из 20 профессий достижима через веса (`tests/data.test.ts`).

## 4. Сверка с исходной методикой

Исходные веса 3-вариантной методики преобразованы в знаковые (верхний вариант `+s`, нижний `−s`, только-средний `+1`) и сверены с единой моделью по направлению (совпадение знаков по вопросам, где хоть у одной модели вес ненулевой): бухгалтер 95%, финансовый аналитик 88%, экономист 82%, остальные — 47–61%. Расхождения сосредоточены там, где единая модель ставит нейтральный 0 вместо слабых ±1 на одиночных вопросах: группировка вопросов по признакам намеренно сглаживает точечные нюансы ради одной системы для всех профессий. Исходный файл сохранён в `docs/legacy-tests-3-options.json` для аудита.

## 5. Контрольные примеры (прогон по итоговым весам)

| Профиль ответов | Результат |
|---|---|
| Все «Нейтрально» (3) | все 20 профессий по 50%, порядок — из `professions.json` |
| «Цифры + регламенты + документы, общение — не моё» (q01,q02,q03,q04,q12,q14,q19 → 5; остальные → 1) | топ: бухгалтер 87%, бухгалтер по зарплате 85%, главный бухгалтер 78%; худшая — специалист по электронной коммерции 17% |
| Все «Абсолютно моё» (5) | верх диапазона: клиентские профессии 100%, низ — бухгалтер 67% |

## 6. Ограничения

- Веса — экспертная модель в рамках методики проекта, не психометрическая валидация. Профили профессий стоит сверить с материалами галереи профессий, когда они появятся; правка — только в `weights` в `tests.json`, код менять не нужно.
- При «прямой линии» (все ответы одинаковые) проценты сжимаются к верху диапазона — свойство любой шкалы Лайкерта без шкалы валидности ответов; её не было и в исходных материалах. Для осмысленных профилей ранжирование различается корректно (раздел 5).

## 7. Тесты и проверка данных

- `tests/scoring.test.ts` — все пять значений шкалы, инверсия при отрицательных весах, нейтральный ответ (50%), пропуски, некорректные значения, исключение профессий без весов, равные результаты (стабильный порядок), крайние значения.
- `tests/data.test.ts` — 20 профессий, распределение по 4 программам, допустимые значения весов (−3…+3), достижимость всех 20 профессий.
- `tests/test-flow.spec.ts`, `tests/gallery.spec.ts` — e2e: прохождение, переход из результата в карточку профессии, галерея с поиском и фильтром, направления.
